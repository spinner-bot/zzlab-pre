一、CLIP 生态全景：从单模型到完整技术栈

笔记 03 介绍了 CLIP 的基本原理（双塔对比学习）。但 CLIP 远不止一个模型——围绕 CLIP 发展出了一整套生态：数据筛选（DataComp/MetaCLIP）、训练改进（SigLIP/EVA-CLIP）、缩放定律、以及作为 VLM 标准视觉编码器的"第二条生命"。

1.1 数据工程：CLIP 成功的真正秘密

CLIP 原始论文用了 4 亿图文对——但这 4 亿数据从未公开。开源社区花了整整三年才系统地搞清楚"什么样的数据能训练出好 CLIP"。

📄 DataComp (2023) — 数据筛选的标准化竞赛

核心洞察：DataComp 设计了一个巧妙实验——固定模型架构和超参数，只改变训练数据。参赛者从 12.8B 候选图文对中筛选出最优子集。结果显示：数据筛选策略的差异可以导致 ImageNet 零样本准确率从 3% 到 79% 的巨大差距——数据质量比模型大小更重要。

DataComp 后续演化为 DataComp-1B，成为 CLIP 数据研究的标准测试平台。

📄 MetaCLIP (2023) — 揭秘 OpenAI 的数据管线

核心方法：MetaCLIP 逆向工程了 OpenAI 未公开的数据管线。它使用元数据驱动的策展——从 Wikidata/WordNet 获取概念词条，按概念平衡采样，而非简单的网络爬取。结果：在相同数据量下超越原始 CLIP。

关键发现：CLIP 数据需满足三个条件——① 概念覆盖广泛（不能偏向高频概念），② 图文匹配度高，③ 避免数据泄漏（测试集图片不能出现在训练集中）。

1.2 SigLIP：CLIP 的高效替代

💡 SigLIP vs CLIP：从 Softmax 到 Sigmoid

原始 CLIP 使用 Softmax 对比损失，需要在大 batch 内做全局归一化——batch size 越大越好（OpenAI 用了 32,768）。

SigLIP 做了一个简单的替换：将 Softmax 改为逐对 Sigmoid 损失。每对图文独立判断是否匹配，不再依赖 batch 内的其他样本。这使得训练不再需要巨大 batch size，在更小的计算预算下达到同等甚至更好的性能。

$$\mathcal{L}_{\text{SigLIP}} = -\frac{1}{|B|}\sum_{i=1}^{|B|}\sum_{j=1}^{|B|}\left[y_{ij}\log\sigma(\mathbf{v}_i\cdot\mathbf{t}_j/\tau)+(1-y_{ij})\log(1-\sigma(\mathbf{v}_i\cdot\mathbf{t}_j/\tau))\right]$$

其中 $y_{ij}=1$ 仅当 $i=j$（对角线匹配对）。这本质上是将对比学习解耦为 $B^2$ 个独立的二分类问题。

✅ SigLIP 的行业地位（2025-2026）

SigLIP-SO400M 已成为 VLM 领域最广泛采用的视觉编码器——LLaVA-OneVision、PaliGemma、Qwen2-VL 等主流 VLM 均采用 SigLIP 而非原始 CLIP。Jina AI 2025 年大规模调查确认：SigLIP 2 (400M 参数) 在大多数 VLM 基准上超过 InternViT-6B (5.9B 参数)——训练方法远大于编码器大小。

二、视觉编码器演进：从 ViT 到多尺度巨人

笔记 03 提到了 ViT 和 CLIP ViT。但 VLM 的视觉编码器在过去两年经历了远比架构更剧烈的演化——分辨率、多尺度、训练方法的改进使得相同参数的编码器性能翻倍。

2.2 DINOv2：纯视觉自监督的巅峰

📄 DINOv2: Learning Robust Visual Features without Supervision — Meta, 2023

DINOv2 证明了纯视觉自监督学习可以产生与弱监督（CLIP）相媲美甚至更优的视觉特征。不需要任何文本数据，仅通过图像级别的自蒸馏（teacher-student + centering），在 142M 张精选图像上训练。

关键特性：DINOv2 特征具有涌现的语义分割和深度估计能力——仅用简单的线性探针就能在语义分割、深度估计等密集预测任务上达到接近监督方法的水平。

2.3 分辨率之战：如何"看"得更清楚

VLM 面临一个根本矛盾：高分辨率 = 更多 visual tokens = 二次增长的注意力成本和 KV 缓存压力。以下是工业界为解决这个矛盾发展出的核心策略：

💡 Qwen2.5-VL 的原生分辨率——范式突破

传统 VLM 将图像缩放到固定尺寸（如 336×336），这导致信息丢失（文档文字模糊、远距离物体不可见）。AnyRes 通过分块缓解了这个问题，但引入了"块间不连续"的新问题。

Qwen2.5-VL 通过 M-RoPE（多维度旋转位置编码）实现了原生动态分辨率——ViT 可以直接处理任意宽高比的图像，位置编码自动适应实际的 2D 空间布局。这消除了分块-拼接的开销和不连续性。

3.2 LLaVA 家族的完整演化树

🦙 LLaVA 演化树（2023.04 → 2024.12）

LLaVA (2023.04): 单线性层投影 + CLIP ViT-L + Vicuna。证明"视觉指令微调"可行。
LLaVA-1.5 (2023.10): 升级为 2 层 MLP + 336px 输入 + 学术基准优化。成为最广泛使用的开源 VLM 基线。

3.3 2025 年的架构创新

3.3.1 Cambrian-1：多编码器融合（SVA）

Cambrian-1（NYU, 2024）提出了空间视觉聚合器（Spatial Vision Aggregator）——同时使用多个互补的视觉编码器（如 CLIP + DINOv2 + ConvNeXt + SigLIP），通过可学习的交叉注意力将它们的输出聚合为统一的视觉表示。证明了不同编码器确实捕获互补信息——CLIP 提供语义、DINOv2 提供定位、ConvNeXt 提供纹理。

3.3.2 NVLM：动态高分辨率 + 分块式处理

NVIDIA NVLM-72B（2024）实现了输入端的动态高分辨率分块（tiling）——根据原始图像宽高比自适应决定切块方式，每块经 ViT 编码后 tile tag 区分位置，支持最大 6×6=36 块的超大分辨率。

3.3.3 Aria：MoE 视觉编码

Aria（Rhymes AI, 2024）将 Mixture-of-Experts 引入视觉编码——每个 visual token 只激活一小部分专家参数，使得大视觉编码器的推理成本可控。

四、训练策略与 Pipeline 深度

笔记 03 几乎没有涉及 VLM 的训练策略。实际上，VLM 的训练 pipeline 已经从 2023 年的两阶段（预训练→SFT）演化为 2025–2026 年的 5–6 阶段复杂流程，每一步都有明确的设计意图。

4.2 Apple MM1 的关键消融发现

📄 MM1: Methods, Analysis & Insights from Multimodal LLM Pre-training — Apple, Mar 2024

Apple 团队做了 VLM 领域最系统性的消融实验，核心发现（按重要性排序）：

  1. 图像分辨率最重要：增大分辨率带来的增益远超增大编码器或 LLM
  2. 视觉 token 数量与分辨率同等重要——不能靠压缩 token 来节约成本
  3. 视觉编码器的预训练损失比参数量更重要
  4. 连接器设计影响不大（MLP ≈ Q-Former ≈ 交叉注意力——数据量够大时差异消失）
  5. 预训练数据混合策略非常关键：合成 caption + 交错的图文文档 + 纯文本数据按 5:3:2 混合最优

这些发现从根本上塑造了 2024 下半年之后的 VLM 设计方向。

4.4 多阶段 SFT + RLHF/DPO

💡 2025–2026 的后训练共识

1. SFT 不再是一阶段完成——现代 pipeline 在多个高质量子集上渐进式 SFT（先通用 VQA，再 OCR，再 grounding，最后推理/Agent）。

六、视频理解：VLM 在时间维度上的延伸

笔记 03 在视频方面只提到了 Sora（视频生成）。本章补充视频理解 VLM——如何让模型理解动态视觉信息。

6.1 核心挑战

视频 = 图像 × 时间。一秒钟 30 帧意味着一分钟视频产生 1800 帧——如果每帧 576 tokens，总计 1,036,800 tokens，远超所有 LLM 的上下文窗口。因此视频 VLM 的核心问题都是围绕如何高效处理时间维度。

6.3 时序建模的四大路线

🎬 时间维度处理的四大范式

A. 位置编码增强：M-RoPE（Qwen2-VL）将位置编码分解为时间/高度/宽度三个独立维度；V2PE 为视觉 token 分配更小的位置增量。
B. 专用时序编码器：STORM（Mamba）、VideoLLaMA2（3D Conv）在 ViT 之后插入时序处理模块。
C. 循环/记忆机制：VideoLLaMB 用循环记忆跨段传递语义，支持流式处理。
D. Token 筛选/压缩：FlexSelect（NeurIPS 2025）通过跨模态注意力自动选择关键帧，9× 加速。

6.4 时序偏好优化（TPO, 2025.01）

📄 Temporal Preference Optimization for Long-Form Video Understanding

核心创新：不依赖人工标注，通过操纵视频输入生成偏好对——给模型看 (a) 不相关帧和 (b) 不完整帧作为"负样本"，完整视频作为"正样本"，用 DPO 训练。这使得 LLaVA-Video-TPO 在 Video-MME 上从 63.3% 跃升至 71.5%，成为 7B 视频 VLM 的 SOTA。

7.2 关键技术趋势

🔊 从离散 Token 到连续嵌入 —— 音频 LLM 的范式转变

早期语音 LLM（SpeechGPT、Moshi）使用离散语音 token（通过 VQ-VAE 将音频波形量化为离散码本），让 LLM 像生成文本一样生成语音。

2025–2026 年的趋势是抛弃离散 token，直接使用连续嵌入。SALMONN-omni 首次实现了无 codec 的全双工语音理解和生成。优势：① 避免量化信息损失，② 消除了 codec 训练和码本维护的开销，③ 更自然的语音质量。

7.3 全双工：语音交互的"圣杯"

传统语音助手是半双工的——你说完，它听完，它回答，你再说话。这与人际对话完全不同（我们可以在对方说话时打断、补充、用语气表达态度）。

全双工模型（ELLSA、SALMONN-omni、MiniCPM-duplex）实现了：① 同时听和说，② 识别和处理打断（barge-in），③ 用语气和停顿传递信息。

八、3D/点云多模态：让模型理解空间

笔记 03 完全未涉及 3D。本章补充3D 视觉-语言模型的发展。

8.1 从 Point-BERT 到 3D-LLM

📄 Point-BERT (CVPR 2022) — 3D Transformer 的预训练基石

借鉴 BERT 的掩码建模思想，Point-BERT 对点云做 Masked Point Modeling (MPM)——随机遮挡部分点，训练模型预测被遮挡点的坐标。这是 3D 域中的"BERT moment"。

后续影响：几乎所有 2024–2025 年的 3D-LLM（GPT4Point、Uni3D-LLM、PointLLM）都以 Point-BERT 作为 3D 编码骨干。

8.2 3D-LLM 的三条路线

路线代表模型方法
直接对齐 PointLLM, Chat-Scene 点云特征 → MLP 投影 → LLM token 空间
逐步对齐 GPT4Point (CVPR 2024), MiniGPT-3D 点云 → Point-QFormer → 文本空间 → LLM（多阶段训练）
多模态绑定 Point-Bind, Uni3D-LLM 点云+图像+音频+文本 → 联合嵌入空间
📄 GPT4Point (CVPR 2024 Highlight) — 首个点云多模态 LLM

GPT4Point 包含两个核心组件：① Point-QFormer（BERT 风格的跨模态桥，将 3D 点云特征压缩为 LLM 可理解的 token），② Pyramid-XL（自动化分层标注引擎，生成 100 万+ 3D-文本对）。

关键发现：2D VLM（如 LLaVA）在 3D 任务上表现很差——因为 2D 渲染图丢失了多视角信息（如"四面体"在 2D 中只能看到一个三角面）。

8.3 3D 多模态的前沿趋势

  1. 统一理解与生成：UniUGG 实现端到端的 3D 理解和生成
  2. 具身 AI 集成：LEO, 3DLLM-Mem 将 3D-LLM 与机器人物理交互结合
  3. 动态场景理解：Video-3D LLM 引入时序信息
  4. 参数高效微调：Point-PEFT 仅增加 0.6M 参数即可在冻结预训练模型上达到 SOTA

九、统一理解与生成：Any-to-Any 的架构之路

笔记 03 提到了 Janus-Pro 的解耦设计。本章深入剖析统一多模态理解与生成的完整技术路线。

9.1 五大技术路线

路线原理代表模型优点缺点
纯自回归 (AR) 图像离散化为 token，GPT 式逐 token 生成 Chameleon, EMU3 架构统一，实现简单 视觉理解弱（VQGAN 语义差）
解耦 AR 理解用 SigLIP，生成用 VQ-VAE，两个编码器 Janus, Janus-Pro 两件事都做到最优 无法处理交错图文，两个编码器
AR + 扩散 (串行) AR 模型输出条件嵌入 → DiT 解码生成图像 Qwen-Image, OmniGen2 理解强，生成质量高 两阶段推理，额外 DiT
AR + 扩散 (并行/MoT) 共享注意力 + 模态特定前馈网络 Bagel, LlamaFusion 大规模混合预训练 工程复杂
双目标单模型 同模型内 CE 损失（文本）+ 扩散损失（图像） Transfusion, Show-O 单一参数集 训练不稳定，难度大

9.2 Janus-Pro 解耦设计的深层逻辑

💡 为什么"理解"和"生成"需要不同的视觉编码器？

理解的本质是语义压缩——从图像中提取"这是什么"的高层语义，扔掉无关细节。需要语义对齐的编码器（如 SigLIP）。

生成的本质是像素重建——从文本恢复"这长什么样子"的每个像素细节。需要重建保真度高的编码器（如 VQ-VAE）。

这两类编码器目的相反——一个追求丢弃信息（抽象），一个追求保留信息（还原）。Janus 的"解耦"实际上是对这个根本矛盾的诚实回应。

9.3 Bagel (ByteDance, 2025) — MoT 范式的开创者

📄 BAGEL: Bootstrapping All GEnerative Latents — ByteDance, May 2025

Bagel 提出 Mixture-of-Transformer-Experts (MoT)——共享 Transformer 的注意力层，但为不同模态分配独立的 FFN 专家。理解路径使用 SigLIP 编码器，生成路径使用 VAE 编码器，两者共享注意力的"通用推理"部分。

意义：Bagel 是最早进行超大规模混合模态预训练的模型之一——从零开始同时训练文本、图像理解和图像生成。

🔮 核心未解问题（截至 2026.07）

"理解+生成统一"是否真的带来 1+1>2 的协同效应？初步证据（Bagel 的大规模混合预训练、Qwen-Image 的生成质量提升）表明更好的文本编码确实能改善图像生成——但在理解任务上，统一模型是否优于专用模型？这个问题仍在验证中。

十、多模态 Agent：从"看懂"到"会用"

笔记 03 完全没有涉及 Agent。本章补充VLM 驱动的 GUI Agent 和自主操作这一 2025–2026 年最热门的应用方向。

10.1 核心范式：纯视觉 GUI 控制

传统 GUI Agent 依赖于 HTML DOM / Accessibility Tree——解析网页结构来定位元素。2025–2026 年的范式转变是纯视觉驱动的 GUI Agent——模型只看屏幕截图，不接触底层 DOM。

💡 为什么纯视觉？

① 通用性：桌面应用、移动 APP、游戏等没有 DOM；② 隐私：截图不暴露底层数据；③ 鲁棒性：网页改版不影响模型（因为 DOM 变了但视觉没变）；④ 简单性：单一输入模态 → 更紧凑的 pipeline。

十一、VLM 缩放定律

笔记 03 虽提到了"训练方法 > 编码器大小"，但没有系统性地讨论缩放定律。本章深度展开。

11.1 三大缩放定律发现

📄 Inference Optimal VLMs Need Fewer Visual Tokens and More Parameters — ICLR 2025

反直觉发现：在固定推理预算下，最优配置是最大化 LLM 参数量 + 最小化 visual token 数量——极端情况下只需 1 个 visual token。这意味着之前所有 VLM 都在"浪费"计算在过多的 visual token 上。
推论：token 压缩比（compression ratio）是 VLM 效率的关键杠杆——比增加 LLM 或视觉编码器大小的回报更高。

📄 Inference Compute-Optimal Video VLMs — ACL 2025

发现：视频 VLM 的最优配置是 (LLM 大小, 帧数, token/帧) 的三维联合优化，且最优分配强烈依赖于微调数据的大小。
实用指导：数据多时可以多分配帧数；数据少时优先增大 LLM 并减少帧数。

📄 FastVLM: Efficient Vision Encoding — Apple, CVPR 2025

发现：通过混合 CNN-ViT 编码器（FastViTHD），在 1152×1152 分辨率下实现 85× TTFT 加速（vs LLaVA-OneVision）。关键在于：视觉编码器架构设计是缩放的关键因子——只优化 LLM 或 token 数量不够，编码器本身的延迟-精度 Pareto 前沿也需要 push。

11.2 缩放定律的实践指导

约束优先投入方向原因
推理延迟敏感视觉 token 压缩 → 编码器效率Token 数量二次影响注意力计算
训练数据有限增大 LLM → 数据增强大 LLM 更需要数据，但有更好的 zero-shot
推理预算充足增大图像分辨率分辨率是准确率的最强杠杆（MM1 结论）
追求全能分辨率 + 多编码器不同任务需要不同的视觉特征

十二、安全与幻觉：多模态模型的暗面

笔记 03 未涉及安全。本章补充VLM 的幻觉、越狱和安全性研究。

12.1 幻觉：VLM 的"睁眼说瞎话"

⚠️ 多模态幻觉的独特挑战

VLM 的幻觉比纯文本 LLM 更复杂：纯文本幻觉是"编造事实"；VLM 幻觉包括：
① 物体幻觉：说"图中有狗"但图中没有狗
② 属性幻觉：说"红车"但车是蓝色的
③ 关系幻觉：说"A 在 B 上面"但 A 在 B 下面
④ 文本幻觉：编造图中不存在的文字
⑤ 上下文幻觉：忽略图像，完全基于文本先验回答（回答了"一般情况"而非"图中情况"）

12.2 多模态越狱

📄 Jailbreaking LLMs & VLMs: Mechanisms, Evaluation, and Unified Defense (Jan 2026)

核心发现：VLM 的越狱比纯文本 LLM 更加复杂——攻击者可以在图像中嵌入恶意指令（如将文字嵌入图片），或利用跨模态不一致（文本安全但图像不安全）。

攻击分类：模板/编码攻击、上下文操纵攻击、对抗学习攻击、LLM 辅助攻击、图像扰动攻击、跨模态传递攻击。

防御框架：感知层（输入检测）+ 生成层（安全解码）+ 参数层（偏好对齐）三层防御。

12.3 红队测试与防御

工作类型关键贡献

🛡️ 防御最佳实践

1. 输入过滤：在视觉编码后、LLM 前插入安全检测模块
2. 安全对齐 SFT：用 RTVLM 等红队数据做安全微调——提升 10-13% 安全性
3. 多模态一致性检查：确保模型的文本推理与视觉证据一致（将防幻觉与防越狱结合）
4. 自动化红队：持续生成新的攻击样本来迭代防御
