PAPER 1 · arXiv: 2306.13649 · ICLR 2024
GKD — On-Policy Distillation of Language Models
R. Agarwal, N. Vieillard et al. · Google DeepMind
一句话核心贡献：在 LLM 时代正式命名 OPD (On-Policy Distillation) 的奠基论文。证明学生在自生成 rollout 上的蒸馏在 token 效率上同时击败 SFT 和 RL，奠定了整个 OPD 领域的范式基础。
📄 P1 · S2/5

背景动机 · 问题定义

🔴 离线蒸馏的致命缺陷

传统 KD: 教师生成固定数据集→学生训练。但训练-推理分布不匹配：学生训练时看到的状态(教师数据分布)与推理时自己生成的状态(学生分布)不同→性能损失。这一问题在 LLM 中因自回归生成而尤为严重。

🟡 GKD 的解决方案

让学生自己生成 rollout (满足 C1)→教师在这些学生样本上提供逐 token logit 监督 (满足 C2)→学生的训练分布 = 推理分布→消除分布不匹配。

实验与关键结果

核心实验发现：
• GKD 在 相同 token 预算下，显著优于 SFT 蒸馏和纯 RL
• 在线采样 (学生自采样) 是性能提升的关键——分布匹配收益 > 教师数据质量
• Reverse KL 在大多数任务上优于 Forward KL——模式追寻更适合 LLM 蒸馏
• 学生规模越小，GKD 相对于 SFT 的优势越显著

MiniLLM — Knowledge Distillation of Large Language Models
Y. Gu, L. Dong et al. · Microsoft / 清华大学

📄 P2 · S2/5

背景动机 · 方法

🔴 标准 KD 的局限

标准 KD 使用Forward KL——要求学生覆盖教师的所有模式。但学生能力有限→无法同时覆盖→分布过于分散→生成质量下降。MiniLLM 选择 Reverse KL: 学生只需集中在教师高概率区域。

🔑 Reverse KL + PG

$$\nabla_\theta \mathcal{L} = \mathbb{E}_{y\sim\pi_S}[-\nabla_\theta \log\pi_S(y) \cdot D_{KL}(\pi_S\|\pi_T)]$$使用 Policy Gradient 直接优化 Reverse KL——因为 Reverse KL 对 π_S 的梯度不能直接通过参数求导。

📄 P2 · S3/5

实验 · 局限

关键发现：MiniLLM 在指令遵循和文本生成上显著优于标准 KD——Reverse KL 的模式追寻更适合 LLM。
局限：① Reverse KL 的模式坍缩风险 (后来 REOPOLD 专门解决) ② PG 训练的方差较大 ③ 需要教师实时前向→计算开销高。
📄 P2 · S4/5

GKD vs MiniLLM 对比

两大奠基论文的差异：
• KL 方向：GKD 同时支持 FKL/RKL；MiniLLM 只用 RKL
• 优化方法：GKD 用标准梯度；MiniLLM 用 Policy Gradient
• 历史地位：GKD 命名了 OPD 并建立通用框架；MiniLLM 率先证明了 RKL+PG 在 LLM 蒸馏中的有效性
• 共同遗产：两者共同开启了白盒 OPD 的范式——学生自采样 + 教师逐 token 监督
📄 P2 · S5/5

影响与后续

MiniLLM 的 RKL+PG 方案直接启发了后续一整条技术线：DistiLLM (Skewed-KL 混合 FKL/RKL)→Entropy-Aware OPD (动态 KL 方向)→REOPOLD (解决 RKL 的模式坍缩/近零奖励/重尾负奖励)。从 MiniLLM 到 REOPOLD，KAIST 团队用了 3 年完成了 RKL 从"有用但不稳定"到"生产就绪"的进化。

背景 · OPD 与 RL 的关系

标准 RL 训练中，KL 正则项 −β·D_KL(π_θ‖π_ref) 用于防止策略偏离太远。OPD 的巧妙之处：把 π_ref 换成更强的教师策略 π_T。原本用于"约束"的 KL 项瞬间变成了"学习"的驱动力——不需要额外的蒸馏步骤。
📄 P3 · S3/5

核心洞察：为何 OPD 同时击败 SFT 和 RL

SFT：学生只在教师见过数据上训练→分布不匹配→泛化差
纯 RL：学生自己探索但奖励稀疏→效率极低
OPD：学生自己探索(在线采样) + 教师提供密集逐 token 信号(KL 监督)→两全其美

📐 前总 · 1/3

什么是白盒 OPD？

🎯 定义
白盒 OPD 使用教师 logits / log-probabilities，在学生自生成 rollout 上进行逐 token 监督。教师模型的内部概率分布完全可见→可以进行精细的 token 级 KL 散度匹配。
与其他 OPD 类型的区别：
• 白盒 vs 黑盒：白盒有 logits 访问→逐 token KL；黑盒仅有标量信号
• 白盒 vs OPSD：白盒有独立外部教师；OPSD 师生同模型
• 白盒 vs OPD-RL：白盒纯蒸馏；OPD-RL 将 OPD 嵌入 RL 训练循环
📐 前总 · 2/3

白盒 OPD 的四个关键设计维度

① KL 方向

Forward KL (覆盖模式) vs Reverse KL (追寻模式) vs Skewed-KL (自适应混合)。决定学生如何模仿教师分布。

② 数据源管理

纯在线 (学生自采样) vs 纯离线 (教师数据集) vs 混合 (AdaSwitch 自适应切换)。决定训练数据从哪来。

③ 信号聚焦

哪些 token 值得蒸馏？全词表 vs Top-K (CR-OPD) vs 高熵 token (REOPOLD/TIP) vs 推理前缀 (Fast OPD)。

④ 约束类型

软约束 (KL 惩罚项) vs 硬约束 (CMDP)。以及特殊约束：跨 tokenizer (DSKDv2)、否决机制 (Veto)、特征空间 (OPRD)。

📄 P10 · Structure 2/7

背景动机 · 问题定义

🔴 背景：LLM 蒸馏的困境

Knowledge Distillation (KD) 是压缩 LLM 的主流方法——用大教师模型的输出分布训练小学生模型。但标准 KD 使用教师预生成的固定数据集（离线数据）→ 训练-推理分布不匹配 → 学生无法覆盖教师行为空间。

🟡 已有尝试

MiniLLM (2023) 首次提出用 Reverse KL + Policy Gradient 实现在线蒸馏——学生在自己生成的 rollout 上模仿教师。但 Reverse KL 有模式追寻 (mode-seeking) 问题：学生只集中在教师的高概率区域，丢失多样性。

🎯 DistiLLM 要解决的问题
$$\min_\theta \mathcal{L}(\theta) = D(\pi_T \|\pi_\theta)$$
其中 D 是衡量师生分布差异的散度。核心问题：应该用哪种散度 D？
• Forward KL D_KL(π_T‖π_S)：覆盖模式 (mean-seeking)→ 多样性好但可能过度分散
• Reverse KL D_KL(π_S‖π_T)：追寻模式 (mode-seeking)→ 锐度高但模式坍缩风险
• 是否存在中间地带？
📄 P10 · Structure 3/7

核心创新：Skewed KL Divergence

DistiLLM 提出 Skewed KL——在 Forward KL 和 Reverse KL 之间通过一个偏度参数 λ进行连续插值，实现从"覆盖模式"到"追寻模式"的平滑过渡。
$$SKD(\pi_T \|\pi_S; \lambda) = \sum_{y} \pi_T(y)^\lambda \pi_S(y)^{1-\lambda} \cdot \log\frac{\pi_S(y)}{\pi_T(y)}$$

λ=0 → Reverse KL

标准 RKL → 模式追寻。学生集中在教师高概率区域。

λ=1 → Forward KL

标准 FKL → 覆盖全部模式。学生覆盖教师所有可能性。

0<λ<1 → Skewed

在两种模式间平滑插值→兼顾覆盖与锐化。λ 可固定或动态调度。

背景动机

全序列 OPD 的计算瓶颈：标准 OPD (GKD/MiniLLM) 对生成序列的每一个 token都计算教师-学生 KL 散度。但在实际推理链中，大量 token 是功能词/填充词——师生对这些 token 的预测几乎一致 (KL≈0)。计算这些位置的 KL 几乎不贡献学习信号，却消耗了绝大部分算力。这与 REOPOLD 的问题二 (近零奖励) 根源相同。

推测解码的启发：推测解码 (Leviathan et al., 2023) 中，draft 模型快速生成候选 token → 目标模型并行验证 → 仅在拒绝位置纠正。SpecKD 将这一思想移植到蒸馏场景。
📄 P11 · S3/6

问题定义

🎯 如何在不牺牲蒸馏质量的前提下，跳过师生一致的低信息量 token？
将全序列 OPD 损失从对每个 token 的 KL 求和，改为仅在"教师不同意学生"的 token 子集上计算：$$\mathcal{L}_{\text{full}} = \sum_{t=1}^{T} D_{KL}(\pi_T \|\pi_S) \quad \rightarrow \quad \mathcal{L}_{\text{gated}} = \sum_{t \in \mathcal{S}} D_{KL}(\pi_T \|\pi_S)$$其中 $\mathcal{S} = \{t : \text{disagree}_t\}$ 是教师与学生输出不一致的 token 位置集合。

📄 P12 · S2/4

背景动机 · 对比式设计

🔴 DistiLLM v1 的局限

Skewed KL 只用单一 λ 混合 FKL/RKL，且不区分数据来源。教师数据和学生数据被同等对待→两种数据的不同特性(教师数据=高质量稳定/学生数据=在线且噪声)没有被利用。

🟡 核心洞察

教师数据上：分布固定、高质量→适合 FKL 覆盖教师所有合理行为。
学生数据上：分布随训练变化、有噪声→适合 RKL 在自己犯错处锐化。
→ 不同数据源配不同 KL 方向

$$\mathcal{L} = \underbrace{D_{KL}^{skew}(\pi_T \|\pi_S)}_{\text{教师数据: Forward}} + \lambda \cdot \underbrace{D_{KL}^{skew}(\pi_S \|\pi_T)}_{\text{学生数据: Reverse}}$$
📄 P12 · S3/5

方法：对比式双路径训练

$$\mathcal{L} = \underbrace{D_{KL}^{skew}(\pi_T \|\pi_S)}_{\text{教师数据: Forward KL}} + \lambda \cdot \underbrace{D_{KL}^{skew}(\pi_S \|\pi_T)}_{\text{学生数据: Reverse KL}}$$训练流程：① 从两个数据源并行采样——教师固定数据集 + 学生在线 rollout → ② 教师数据路径用 Forward KL (覆盖教师所有合理行为) → ③ 学生数据路径用 Reverse KL (在自己犯错处锐化) → ④ 联合损失反向传播。λ 控制学生路径的相对权重。
📄 P12 · S4/5

实验 · 2×2 矩阵先驱

DistiLLM-2 的对比式设计 直接启发了后续的 2×2 前缀×KL 统一框架 (Module 1 Part 5)。它同时覆盖了象限① (教师前缀+FKL) 和象限④ (学生前缀+RKL)，证明了两种模式的 互补性——ICML 2025 Oral 的接受标志着学术界对"解耦数据源与KL方向"这一思想的高度认可。

DSKDv2 — Cross-Tokenizer Distillation with On-Policy Support
BJTU (北京交通大学)
核心贡献：首次解决师生使用不同 tokenizer时的 OPD 问题——通过跨 tokenizer 投影对齐机制，使得即使词汇表不对齐 (如教师用 Llama tokenizer, 学生用 Qwen tokenizer) 也能进行 token 级 KL 监督。支持 on-policy 模式。
📄 P13 · S2/5

背景动机

标准 OPD 假设师生使用相同 tokenizer——token 级 KL 散度直接定义在共享词汇表上。但实际场景中，教师和学生常使用不同 tokenizer (如 Mistral vs Llama tokenizer)。此时 KL 散度失去直接意义——两个分布定义在不同的概率空间上。这与 CASIA Revisiting OPD (P4) 的失效模式③完全相同。
📄 P13 · S3/5

核心方法：跨 Tokenizer 投影

DSKDv2 通过投影矩阵 W将学生 token 分布 π_S 线性映射到教师 token 空间：π_S→T = W · π_S。然后在教师空间中计算 KL(π_T ‖ π_S→T)。投影矩阵 W 通过共享文本上师生 token 的共现统计来学习——哪些学生 token 对应哪些教师 token。
📄 P13 · S4/5

实验 · 意义

支持 on-policy 模式——学生可以在自生成 rollout 上进行跨 tokenizer 蒸馏。这为异构模型间的 OPD打开了可能性：教师和学生可以来自完全不同的模型家族。与 P4 的 tokenizer 不匹配诊断形成问题-解决方案闭环。
📄 P13 · S5/5

局限与审视

投影矩阵 W 引入额外参数和计算开销——每对 tokenizer 需要单独训练。tokenizer 差异过大 (如 BPE vs SentencePiece) 时对齐精度下降。是否值得为跨 tokenizer 支持引入额外复杂度，取决于具体部署场景。

华为诺亚方舟实验室

背景动机

黑盒场景的核心挑战：教师仅提供文本输出或 API 响应——无法获取 token 级 logits。对比学习 (ORPO) 和序列评分 (OVD) 提供稀疏信号，训练效率受限。GAD 受 GAN 启发：生成器+判别器的对抗框架已被证明在图像生成中极其有效——能否将其移植到语言模型的蒸馏中？
📄 P31 · GAD ⭐ S3/8

问题定义

🎯 如何构造一个能从教师文本输出中提取稠密训练信号的机制？
给定：教师 API π_T (仅输出文本，无 logits)，学生策略 π_S。
目标：训练 π_S 使其输出分布逼近 π_T，但不访问 π_T 的内部概率。
GAD 方案：训练判别器 D_φ 区分 π_T 输出 vs π_S 输出→判别器评分作为稠密奖励信号→学生通过 PG 最大化该奖励。
📄 P31 · GAD ⭐ S4/8

核心创新点

① 对抗判别器

训练 D_φ 二分类：输入文本来自教师 or 学生。判别器捕捉的是分布级差异——比 token 级 KL 更全局。

② 在线 RM

随学生策略更新，判别器也持续训练——保持对当前学生输出的区分能力→奖励信号不退化。

③ PG 优化

学生通过 Policy Gradient 最大化判别器评分——不需要 token 级 KL，仅需标量奖励。

📄 P31 · GAD ⭐ S5/8

方法细节

三步循环训练：
① 学生 π_S 从 prompt 集采样生成响应 y_S
② 教师 π_T 对同一 prompt 生成响应 y_T
③ 判别器 D_φ 对每对 (y_T, y_S) 输出"来自教师"的概率→作为奖励 R(y_S)
④ 学生通过 PG 最大化 E[R(y_S)]，判别器通过 BCE 最小化分类误差
⑤ 重复——判别器和学生交替更新，互相提升
