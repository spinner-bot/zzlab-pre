Part 1 知识结构图

时间线 · 2020–2022

ViT · 2020.10
arXiv: 2010.11929 · ICLR 2021 · Google · 引用 50,000+
ViT — An Image is Worth 16×16 Words
核心贡献：首次将标准 Transformer 直接应用于图像——把图像切成固定大小的 Patch，当作"视觉单词"序列处理，打破 CV 和 NLP 的架构壁垒。

ViT 架构：图像 → Patch → Transformer

🔑 关键创新

图像不需要专门的卷积操作。把图像切成 Patch 后线性投影，变成和文本 token 一样的向量序列——Transformer 自然地就能处理。这打破了 CV 和 NLP 的架构壁垒。

⚠️ 局限

ViT 需要大量数据预训练（JFT-300M）才能超越 CNN。缺少卷积的归纳偏置——平移等变性、局部性——在小数据集上不如 ResNet。

CLIP · 2021.01
arXiv: 2103.00020 · OpenAI · 4亿图文对 · 引用 30,000+
CLIP — Contrastive Language–Image Pre-training
核心贡献：用对比学习在4亿图文对上训练，将图像和文本映射到同一个语义空间。"一只狗"的文字和狗的照片在这个空间中距离极近。

CLIP 架构：双塔 + 对比学习

DALL·E 1 · 2021.01
OpenAI · 2021.01 · Zero-Shot Text-to-Image Generation
DALL·E — 首个大规模文本→图像生成
核心创新：分两步——① 用dVAE将图像压缩为离散token序列；② 用自回归Transformer像GPT一样逐token生成这些图像token。首次证明语言和视觉可在同一token流中统一建模。

核心问题：如何让 Transformer 生成图像？

🎯 根本矛盾
Transformer 是为一维离散序列（文本token）设计的——每个位置是词表中一个整数索引。但图像是二维连续像素值（256×256×3个数字）。

解决思路：能不能把图像也变成一串整数索引？就像把中文翻译成数字token一样，把一张图也"翻译"成一串数字。这样Transformer就能用完全相同的方式处理文本和图像。

dVAE：图像的"翻译器"

两步流程：dVAE + 自回归 Transformer

Codebook 训练细节 & 为什么必须离散化

📖 Codebook 如何训练

① 编码器输出连续向量 z_e → ② 与8192个条目计算距离 → ③ 选择最近的条目e_k → ④ argmin不可导→用直通估计器(STE)：前向用量化e_k，反向传梯度给编码器 → ⑤ codebook通过指数移动平均(EMA)更新。条目逐渐变成常见纹理/边缘/色彩模板。

🔑 为什么必须离散化

如果直接预测连续像素值→MSE损失→输出成为所有可能图像的平均值(模糊)。
离散token将生成从"连续回归"变成"分类问题"→可用标准交叉熵训练Transformer。
代价：量化误差(有损压缩)，但保留语义、剔除噪声。

支线：自回归生成 & 潜空间

📝 自回归生成

模型逐个token生成序列。每步预测下一个token的概率分布→采样→拼回输入→预测再下一个。DALL·E中：先输入文本token，再逐个生成1024个图像token。

🌐 潜空间 (Latent Space)

神经网络的压缩表示空间。VAE将512×512×3图像压缩至64×64×4——数据量1/48。保留语义信息，剔除高频纹理噪声。

MSE均值回归 · 四种生成方案

⚠️ 均值回归

MSE最优解=E[y|x]——期望值。当真实分布多峰时，期望落在峰间→模糊的叠加平均。这是所有确定性损失函数的宿命。

✅ 四种方案

VAE高斯+KL正则偏模糊
GAN对抗采样不稳定
扩散分步MSE慢
离散化量化+交叉熵量化误差

设计哲学：连续 vs 离散

💡 两种哲学，同一个核心目标
离散搭桥：连续→离散token→Transformer(交叉熵)→离散→连续。代价=量化误差，收获=稳定训练。
连续分步：不一步预测，分几百步去噪。每步MSE目标变成确定的高斯噪声→完全避开均值回归。
共同核心：如何避开"直接预测连续多峰分布"这一灾难。

Stable Diffusion 三组件

SD 采样伪代码逐行解释

def sd_sampling(prompt, num_steps=50):
  text_embed = CLIP_text_encoder(prompt)  # ① 文本→条件向量
  z = torch.randn(1, 4, 64, 64)          # ② 随机噪声(潜空间64×64×4)
  for t in reversed(range(num_steps)):
    noise_pred = UNet(z, t, text_embed)  # ③ 预测当前噪声(条件=文本)
    z = denoise_step(z, noise_pred, t)  # ④ 减去噪声 → z更接近干净潜变量
  image = VAE_decoder(z)              # ⑤ 潜空间→像素
  return image
关键洞察：每步MSE预测的是噪声(确定性),而非最终图像(多峰分布)。将一次生成拆成50步→每步MSE目标都是确定值→完美避开均值回归。

桥接模式：视觉 → 语言的理解路径

Flamingo (2022.04)

Perceiver Resampler：将变长视觉特征压缩为固定64个token→通过交叉注意力注入LLM每一层。首个大规模VLM，80B参数，强大Few-shot能力。

BLIP-2 (2023.01)

Q-Former：轻量Transformer(仅100M参数)。可学习query tokens从ViT特征中提取语言相关信息→输出固定数量视觉token→作为软提示(soft prompt)输入冻结LLM。

从单模型到完整技术栈 · 笔记06 深度补充

内容结构图

横向浏览 → 在进入每个部分前高亮当前位置

1. CLIP 未公开的数据管线

OpenAI 在 CLIP 论文中描述了使用4亿图文对进行训练，但从未公开数据收集和筛选的具体方法。开源社区面临核心问题：如何复现甚至超越 CLIP？

两条路径：① 大规模数据筛选基准 (DataComp) ② 逆向工程 OpenAI 的数据管线 (MetaCLIP)。

2-1. DataComp (2023)

核心贡献：建立大规模多模态数据筛选的标准化基准。DataComp 不是一种数据筛选方法，而是一个竞赛平台——提供统一的原始数据池和评估协议，让不同筛选算法在公平条件下比较。

关键发现：数据筛选算法的重要性远超模型架构——最好的筛选策略用较小模型就能达到甚至超越 CLIP 的性能。

2-2. MetaCLIP — 逆向工程 OpenAI 数据管线

核心方法：使用元数据驱动的策展 (Metadata-driven Curation)——从 Wikidata/WordNet 获取概念词条，按概念平衡采样，而非简单的网络爬取。在相同数据量下超越原始 CLIP。

关键在于"概念平衡"：原始网络爬取会导致高频概念（如"狗"、"车"）占据大量训练样本，而稀有概念（如"鸭嘴兽"）几乎不可见。MetaCLIP 确保了每个概念都有足够的训练样本。

2-2a. 什么是概念平衡？

⚖️ 概念平衡采样的含义

不按数据出现频率采样，而是按概念多样性采样。每个概念（来自 Wikidata 的数万个条目）获得大致相等的样本配额。这避免了模型被高频概念主导，强制学习长尾知识。

📊 三个核心结论 (2-2rs)

① 概念平衡显著提升零样本迁移——尤其对稀有类别
② 数据量不是越多越好——平衡的4亿样本超越不平衡的10亿
③ 元数据策展成本极低——Wikidata/WordNet 是免费知识库

2-2b. MetaCLIP 核心方法精讲

三步管线：① 从 Wikidata/WordNet 获取数十万概念词条作为查询 → ② 对每个概念查询网络数据，按配额采样（每概念约5000样本）→ ③ 用平衡后的数据集训练 CLIP。

关键洞察：OpenAI 的"4亿图文对"并非随机网络爬取——MetaCLIP 通过逆向工程发现，其优越性来自隐式的概念平衡策展。这解释了为什么简单扩大网络爬取数据（如 LAION-5B）并不能线性提升性能。

3. SigLIP — sigmoid 替代 softmax

核心创新：将 CLIP 的对比损失从softmax（全局归一化）替换为sigmoid（逐对独立）。

CLIP: 对每个样本，计算它与批次中所有其他样本的 softmax 概率（需全局归一化，batch size 敏感）。
SigLIP: 对每个图文对 (i,j)，独立判断它们是否匹配——一个二分类问题（0=不匹配, 1=匹配），不再需要 batch 内全局归一化。

3pre. softmax vs sigmoid

softmax (CLIP)

$$\mathcal{L}=-\frac{1}{N}\sum_i\log\frac{\exp(s_{ii})}{\sum_j\exp(s_{ij})}$$所有 N 个候选竞争一个"正确"位置。需要大 batch，且 batch size 直接影响性能。

sigmoid (SigLIP)

$$\mathcal{L}=-\frac{1}{B^2}\sum_{i,j}[y_{ij}\log\sigma(s_{ij})+(1-y_{ij})\log(1-\sigma(s_{ij}))]$$每个 (i,j) 对独立二分类。本质：将对比学习解耦为 B² 个独立的二分类问题。

4. EVA-CLIP 与缩放定律

EVA-CLIP 的核心工作：系统研究 CLIP 训练的缩放行为——模型大小、数据量、训练计算量三者如何影响最终性能。

精讲要点 (4-1 → 4-2 → 4-9)：
• 4-1：在给定计算预算下，更大的模型 + 更少的 epoch优于小模型多轮训练
• 4-2：数据质量和多样性比数据量更重要——呼应 MetaCLIP 的发现
• 4-9 核心洞察：CLIP 训练的最优数据量随模型规模呈幂律增长

5. CLIP 生态全景 · 小结

CLIP未公开管线 → DataComp建立基准 → MetaCLIP逆向概念平衡 → SigLIP用sigmoid解耦 → EVA-CLIP量化缩放定律。
核心主线：数据质量 > 模型架构 > 训练技巧。CLIP 的真正秘密不在于双塔对比学习，而在于其未公开的数据策展。

非原生 = 把视觉模块"外挂"到语言模型上，中间加个翻译器。

就像：非原生是把翻译器接到只会中文的人耳边；原生是让这个人从小在多语言环境长大，直接用每种语言思考。

Ch2 · 视觉编码器演进

从 ViT 到多尺度巨人

ViT 之后，视觉编码器沿三条路径演化：① 层级化(Swin/ConvNeXt) ② 自监督(DINOv2) ③ 分辨率扩展(AnyRes/DynamicRes)。

路径一：层级化 (Swin / ConvNeXt)

🔑 核心思想

标准 ViT 所有层使用相同的空间分辨率（14x14 patch）。层级化引入金字塔结构——早期层高分辨率，后期层低分辨率，不同层输出不同尺度的特征图。

📊 代表模型

Swin Transformer：窗口注意力+patch合并→层级特征。ConvNeXt：卷积风格的ViT。VLM中多尺度特征使模型能同时看清细节和把握全局。

路径二：自监督 (DINOv2)

🔑 核心思想

不需要图文对，纯视觉数据即可训练。DINOv2 使用自蒸馏：教师网络(EMA更新)指导学生网络。学到的特征语义连续性极强——相似物体在特征空间自然聚集。

📊 VLM 中的价值

低资源场景：先在大量无标注图像上预训练→少量图文对微调→接近甚至超越CLIP效果。

路径三：分辨率扩展

🔑 核心思想

CLIP/ViT 最初固定 224x224。AnyRes 将高分辨率图切成多个子图分别编码→拼接送入LLM→动态分辨率支持。

📊 关键发现 (Apple MM1)

图像分辨率是VLM性能最重要的单一变量——超过模型大小、连接器设计。直接提升OCR、文档理解。

视觉编码器选择决策树 (2026)

通用VLM：SigLIP-SO400M (性价比最优) 或 EVA-CLIP-18B (性能最强)
高分辨率需求：AnyRes + 层级化编码器
3D/视频：VideoViT / 3D 点云专用编码器
低资源：DINOv2 自监督预训练 + 少量图文对微调

① 交叉注意力 (Flamingo)

训练 Pipeline 演化：LLaVA 2阶段 → 现代5-6阶段

步骤0：编码器对比学习

🔧 如何做

在图文对上用SigLIP 风格的对比损失训练视觉编码器。图文匹配的为正样本，不匹配的为负样本——sigmoid 独立判断每对是否匹配。

💡 为什么需要

CLIP 的预训练数据与VLM实际场景存在分布差异。用目标数据重新训练可让编码器更好适配后续VLM任务。

名词解释

SigLIP 风格

SigLIP 用 sigmoid 替代 CLIP 的 softmax。CLIP: 每个样本与批次中所有其他样本竞争→需全局归一化。SigLIP: 对每个图文对独立判断匹配(0/1二分类)，不再依赖 batch size。更高效，更适合大规模训练。

分布差异

CLIP 在互联网图文对上训练（alt-text, caption），但 VLM 实际面对的是用户提问+多轮对话。训练数据分布 ≠ 使用场景分布→直接使用会产生性能损失。需要在目标分布上重新对齐。

步骤1：跨模态对齐（仅训练连接器）

🔧 如何做

冻结视觉编码器和LLM，仅训练中间的MLP投影层。用图文caption数据训练——让投影层学会将视觉特征"翻译"到LLM能理解的嵌入空间。

💡 为什么需要

视觉编码器输出的是视觉特征空间，LLM期待文本嵌入空间。这步是"翻译层"的训练——对齐两个原本不相通的表示空间。冻结大模型保证了不破坏已有能力。

名词解释

MLP 投影层

MLP = 多层感知机 = 若干全连接层+激活函数。在 LLaVA 中，MLP 将视觉 token 的维度（如 ViT 输出的 1024 维）线性映射到 LLM 嵌入空间（如 4096 维）。是最简单的连接器——仅做维度变换，不引入复杂结构。

Caption 数据

Caption = 图像的文字描述。如"一只橘猫坐在窗台上晒太阳"。用于训练模型看图说话的基本能力。来源：人工标注 / 大模型自动生成（如 ShareGPT4V）。

步骤2：多任务预训练（全参数）

🔧 如何做：解冻所有参数（视觉编码器+连接器+LLM），在多种类型数据上联合训练——caption、VQA、OCR、grounding、交错图文。

💡 为什么需要：步骤1只训练了连接器，视觉和语言模块之间还是"陌生"的。全参数训练让两个模块真正学会协同工作——视觉编码器学会提取LLM需要的特征，LLM学会利用视觉信息。

名词解释：VQA · OCR · Grounding

VQA (视觉问答)

给一张图+一个问题→模型回答。如"图中有几个人？"→需要看图理解+推理。训练数据：(图, 问题, 答案)三元组。

OCR (光学字符识别)

识别图像中的文字——场景文字(路牌)、文档文字(PDF)、手写文字。VLM 必须"会读"才能理解图表/文档。

Grounding (视觉定位)

根据文字描述在图中定位具体区域——"那个红色的球在哪里？"→输出边界框坐标。让模型学会"指哪看哪"。

步骤3：退火（高质量数据精调）

🔧 如何做：用精选的高质量数据（通常10-100倍少于预训练数据）以更小的学习率继续训练。数据严格筛选：答案正确性、格式规范性、任务多样性。

💡 为什么需要：大规模预训练数据中不可避免地包含噪声、错误标注、低质量样本。退火阶段用"纯净"数据修正模型在被噪声污染后产生的偏差，让模型在关键能力维度上做最后的精细调整。类比冶金：高温锻造后缓慢冷却以消除内应力。

步骤4-5：后训练（SFT→MPO→GRPO→RL）

步骤4: SFT → MPO

SFT：在高质量指令数据上监督微调。MPO (混合偏好优化)：结合多种偏好信号（人类偏好+自动评分+对比信号），让模型学会更符合人类期望的回答。

步骤5: GRPO → Alignment RL

LongCoT冷启动→GRPO迭代→最终对齐。整个过程让模型的推理和指令遵循能力螺旋上升。

偏好信号专题

👤 人类偏好

让人类标注员比较两个回答，选出更好的一个。数据格式：(图, 问题, 好回答, 差回答)。最可靠但也最昂贵——用于训练奖励模型(RM)或直接DPO优化。

🤖 自动评分

用规则/模型自动打分——如答案正确性(数学题)、格式规范性、与参考答案的相似度。便宜可规模化，但可能被"钻空子"(reward hacking)。

⚖️ 对比信号

不需要绝对评分，只需比较两个输出的相对好坏。DPO/MPO都基于对比信号。优势：相对判断比绝对打分更容易、更一致(人擅长比较，不擅长打分)。

名词解释：LongCoT · SFT

LongCoT (长推理链)

Chain-of-Thought = 不仅给出答案，还给出中间推理步骤。LongCoT = 很长的推理链(数百token)。如："先分析条件→列方程→逐步求解→验证→最终答案"。用LongCoT数据做SFT可以让模型学会"慢思考"。

SFT (监督微调)

Supervised Fine-Tuning = 在带标签的高质量数据上训练模型。给定输入，让模型输出尽可能接近标签。损失函数通常是交叉熵。简单、稳定，是RL之前的标准"热身"步骤。

步骤4 精讲：SFT → MPO

阶段一 SFT (监督微调)：
在高质量指令数据上训练模型。数据包含各种任务类型——VQA、caption、OCR、推理——每种都有明确的输入-输出对。目标是让模型学会理解并遵循图文指令。损失函数=交叉熵——最大化正确输出的概率。

阶段二 MPO (混合偏好优化)：
SFT 只教模型"正确回答"，但没教它"什么回答更好"。MPO 引入多种偏好信号：人类偏好(更好vs更差)、自动评分(正确性/格式)、对比信号(相对好坏)。将这些信号混合加权，训练模型不仅正确，还要符合人类期望。

步骤5 精讲 (上)：LongCoT 冷启动

LongCoT 冷启动是什么？
用包含长推理链的高质量数据对模型做 SFT。这些数据中，每个答案都包含完整的推理过程——"先分析→列步骤→逐步求解→验证"。

为什么叫"冷启动"？
RL 训练需要一个合理的初始策略。如果模型完全不会推理，RL 在稀疏奖励下几乎无法起步(与 Module 1 中"梯度场不存在"同理)。先用 LongCoT SFT 让模型获得基本的推理能力——这就是"冷启动"——然后再用 RL 进一步强化。

步骤5 精讲 (下)：GRPO → Alignment RL

GRPO (组内相对策略优化)：
对同一个问题，模型生成多条回答(如 8 条)→根据奖励函数(正确性+格式)给每条打分→组内标准化(减去组内均值，除以组内标准差)→优势高的回答被强化，低的被抑制。不需要单独的 Critic 网络。

最终 Alignment RL：
在 GRPO 强化推理能力后，用安全/有用性/指令遵循的奖励函数做最后对齐——确保模型不仅推理强，而且安全可靠、遵循人类意图。

Apple MM1：VLM 最系统性的消融实验

Apple 2024.03 · 五大核心发现（按重要性排序）：

① 图像分辨率最重要——增大分辨率带来的增益远超增大编码器或LLM
② 视觉token数量与分辨率同等重要——不能靠压缩token来节约成本
③ 视觉编码器的预训练损失 > 参数量——好的预训练比更大的模型更重要
④ 连接器设计影响不大——MLP ≈ Q-Former ≈ 交叉注意力，数据量大时差异消失
⑤ 数据混合策略非常关键——合成caption+交错图文+纯文本按5:3:2最优

名词解释

消融实验 (Ablation)

系统性地移除或改变一个组件，观察性能变化。如"去掉OCR数据会怎样？""把分辨率从224换成448？"Apple MM1 用这个方法逐一测试每个设计选择的影响——是最严谨的因果验证方法。

视觉编码器的预训练损失

预训练损失越低 = 编码器从原始数据中提取特征的能力越强。MM1 发现：在相同的参数量下，预训练更充分的编码器对下游VLM的贡献远超参数量更大但预训练不足的编码器。

为什么连接器不重要？数据混合为什么关键？

🔌 连接器设计影响不大

MLP/Q-Former/交叉注意力——三者在数据量足够大时差异消失。因为大量数据让模型有足够的学习机会去弥补连接器表达力的不足。简单MLP在充足数据下也能学会复杂的跨模态映射。这意味着数据 > 架构。

📊 数据混合非常关键

不同类型数据训练不同能力：caption→看图说话，交错图文→多步推理，纯文本→保持语言能力。配比失衡会导致某些能力过强而另一些退化。5:3:2 是 Apple 消融找到的最优平衡点。

🎬 Ch6 · 视频理解

VLM 在时间维度上的延伸

视频理解：核心挑战

🎯 视频 = 图像 × 时间 = 无法承受的 token 量
1 秒 30 帧 × 1 分钟 = 1,800 帧 × 每帧 576 tokens = 1,036,800 tokens——远超所有 LLM 的上下文窗口。视频 VLM 的核心问题：如何高效处理时间维度。

名词解释：帧 · Token · 上下文窗口

🎞️ 帧 (Frame)

视频的基本单位——一秒钟通常有 24-30 帧。每帧是一张完整的 RGB 图像。一分钟的视频有约 1800 帧——如果都送入 VLM，计算量爆炸。

🔤 Token

VLM 将每帧图像编码为固定数量的 视觉 token。如 ViT-L/14 对 336×336 图像产生 576 个 token。帧数 × 每帧token = 视频的总 token 数。

📏 上下文窗口

LLM 一次能处理的最大 token 数。GPT-4 128K，Gemini 1.5 可达 1M+。但即便 1M 窗口，仅够处理不到 1 分钟的未压缩视频。

时序建模四大路线

路线A精讲：位置编码增强 (M-RoPE)

🔑 核心思想

将传统 1D 位置编码扩展为三维独立编码：时间维度(T)、高度(H)、宽度(W)。每个维度有自己的旋转频率——模型学会区分"同一位置但不同时间"和"同一时间但不同位置"。

📊 效果

代表：Qwen2-VL。M-RoPE 使模型能同时理解空间关系（上下左右）和时序关系（前后帧），无需额外时序模块。

路线B精讲：专用时序编码器 (Mamba/3D Conv)

🔑 核心思想

在 ViT 提取每帧特征之后，插入一个专门处理时间维度的模块。STORM 用 Mamba（状态空间模型）处理帧序列；VideoLLaMA2 用 3D 卷积同时聚合时空信息。

📊 Mamba 优势

Mamba 的选择性状态空间机制：根据输入内容自动决定记住什么、遗忘什么——比 Transformer 更高效处理长序列。STORM 因此实现 8× 计算降低。

路线C精讲：循环/记忆机制 (VideoLLaMB)

将长视频分成多个片段 (segment)逐段处理。每个片段提取特征后，通过循环记忆桥 (Recurrent Memory Bridge)将前一段的语义信息传递给下一段——记忆 token 跨越片段边界传递上下文。

关键优势：支持流式处理——可以处理无限长的视频流，不需要一次性装入所有帧。内存消耗恒定，不随视频长度增长。在 Video-MME 上提升 +4.2pt。

路线D精讲：Token 筛选/压缩 (FlexSelect)

核心问题：视频中大多数帧是冗余的——相邻帧几乎相同。为什么要给每一帧都计算 token？

FlexSelect 方案：通过跨模态注意力自动评估每一帧与文本查询的相关性——只选择最关键的帧送入 LLM。NeurIPS 2025 上的结果显示 9× 加速——去掉 90% 的帧，性能几乎不降。

核心洞察："看"不需要"看清每一帧"——人类看视频时也在不断跳跃注意力。

TPO：时序偏好优化 — 深入讲解

🔑 偏好对如何生成

不需要人工标注！通过对视频输入做手脚自动构造：
① 正样本：给模型看完整视频→生成回答
② 负样本A：给模型看不相关帧（随机打乱帧顺序）
③ 负样本B：给模型看不完整帧（删除部分关键帧）
因此偏好信号=完整视频 > 打乱帧 ≈ 缺帧。

📊 DPO 训练过程

用生成的 (正样本, 负样本) 偏好对，通过 DPO 训练模型——最大化完整视频回答的概率，最小化残缺/打乱视频回答的概率。LLaVA-Video-TPO 借此从 63.3% → 71.5%。关键在于不需要昂贵的人工标注。

让模型理解空间

名词解释：点云 · MPM

📐 点云 (Point Cloud)

3D 空间中的离散点集合——每个点有 (x,y,z) 坐标，可能还有颜色、法向量等属性。来自 LiDAR 扫描、深度相机或 3D 重建。与 2D 图像不同：点云是无序的、稀疏的、不规则的——无法直接用 CNN。

MPM (Masked Point Modeling)

Point-BERT 的核心预训练方法：随机遮挡输入点云的部分点→训练模型预测被遮挡点的坐标。类比 BERT 的 Masked Language Modeling——让模型学会 3D 空间的"语法"。是 3D 域的 BERT moment。

3D 点云：从 Point-BERT 到 3D-LLM

Point-BERT (CVPR 2022)

3D 域的"BERT moment"：对点云做 Masked Point Modeling——随机遮挡部分点，训练模型预测被遮挡点的坐标。几乎所有 2024-2025 年的 3D-LLM 都以 Point-BERT 作为 3D 编码骨干。

三条 3D-LLM 路线

① 点云→文本：3D编码→投影→LLM (PointLLM)
② 多视图投影：3D→2D渲染→VLM (GPT4Point)
③ 隐式场表示：NeRF/3D Gaussian Splatting → LLM

Janus-Pro：理解与生成的解耦设计

🧠 理解路径 (SigLIP)

目标：语义压缩——从图像提取"这是什么"的高层语义，扔掉无关细节。需要语义对齐的编码器。输出：文本描述、问答、推理。

🎨 生成路径 (VQ-VAE)

目标：像素重建——从文本恢复"这长什么样"的每个像素细节。需要重建保真度高的编码器。输出：生成图像。

💡 为什么必须解耦
理解追求丢弃信息（抽象），生成追求保留信息（还原）。这两个目标本质矛盾——Janus 的"解耦"是对这个矛盾最诚实的回应。

Ch11 · 缩放定律

VLM 效率的最优配置

Ch11: VLM 缩放定律 — 反直觉发现

🔥 ICLR 2025: 最优配置 = 极少数 visual token + 大 LLM
在固定推理预算下，最优配置是最大化 LLM 参数量 + 最小化 visual token 数量——极端情况下只需 1 个 visual token。这意味着之前所有 VLM 都在"浪费"计算在过多的 visual token 上。

推论：token 压缩比是 VLM 效率的关键杠杆——回报高于增大 LLM 或视觉编码器。

缩放定律的实践指导

约束优先投入方向原因
推理延迟敏感视觉token压缩→编码器效率Token数量二次影响注意力计算
训练数据有限增大LLM→数据增强大LLM有更好的zero-shot
推理预算充足增大图像分辨率分辨率是准确率的最强杠杆
追求全能分辨率+多编码器不同任务需不同视觉特征

Module 2 总结与展望

多模态 AI 的发展是一部"从感知到生成、从单一到统一"的演进史。2020 年 ViT 用 Patch+Transformer 打破了 CV 与 NLP 的架构壁垒，CLIP 在对比如下建立了图文共享的语义空间——这两个基石性的工作让后来的所有 VLM 成为可能。

2021-2022 年，DALL·E 和 Stable Diffusion 从两个方向回答了"如何生成图像"——离散 token 化用交叉熵避开均值回归，潜空间扩散用分步去噪将一次生成拆解为确定性问题。Flamingo 和 BLIP-2 的桥接模式则证明：不需要重新训练，一个轻量的连接器就能让 LLM 学会"看"。

2023 年的 VLM 崛起标志着多模态从实验室走向大众。GPT-4V 向全世界展示了 AI 看图推理的可能性，LLaVA 用视觉指令微调证明了开源社区可以以极低成本追赶闭源。原生与非原生架构之争——Gemini 的"从零多语言生长"vs LLaVA 的"翻译外挂"——至今仍在演进。

CLIP 生态的扩张揭示了一个深刻的规律：数据质量 > 模型架构 > 训练技巧。MetaCLIP 的逆向工程、SigLIP 的 sigmoid 解耦、EVA-CLIP 的缩放定律——每一条线索都在指向同一个结论：数据策展是视觉表征学习的核心秘密。

2024-2026 年，多模态进入了"统一"时代。Any-to-Any 五大技术路线——纯自回归、解耦 AR、AR+扩散串行、MoT 并行、双目标单模型——在回答同一个问题：一个模型能否同时理解和生成所有模态？Janus-Pro 的"解耦"设计给出了最诚实的回答：理解追求抽象舍弃细节，生成追求保留每个像素，两个目标本质矛盾。

多模态 Agent 让模型从"看懂"走向"会用"——纯视觉 GUI 控制不依赖 DOM，截图即输入。缩放定律的反直觉发现（1 个 visual token + 大 LLM）颠覆了设计直觉。五种幻觉类型提醒我们：多模态模型的可靠性问题远未解决。

展望：未来多模态将走向何方？视频与 3D 的理解仍处于早期阶段，全双工语音交互正在成为新范式，Any-to-Any 统一模型的"1+1>2"效应仍在验证中。从 2020 年的 ViT 到 2026 年的 Gemini 3/Claude Opus 4.6，六年时间多模态走完了"从 0 到 1 再到 N"的全过程。但真正的"多模态原生智能"——像人类一样无缝融合视觉、听觉、语言和行动——才刚刚开始。
